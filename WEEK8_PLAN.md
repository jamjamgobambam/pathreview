# Week 8 Plan — Issue #111: Add property-based tests for the PII scrubber

## Issue
- Link: https://github.com/ascherj/pathreview/issues/111
- Goal: Add property-based tests with Hypothesis for the PII scrubber and fix any current edge-case detection bugs.

## Problem summary
- The `PIIScrubber` in `safety/pii_scrubber.py` should reliably redact email, phone, SSN, and street address patterns.
- Existing unit tests covered many cases, but there were no property-based tests.
- While adding this coverage, phone and street address regexes were found to be too weak or too broad.

## Root cause analysis
- `phone_us` regex did not match common US phone formats like `(555) 123-4567` because of overly strict boundaries.
- `street_address` regex was too permissive and could match non-address text segments.
- Hypothesis tests initially used a function-scoped pytest fixture, which conflicts with Hypothesis test execution expectations.
- The generated PII examples in the property-based test were too broad and included invalid values.

## Proposed solution
- Strengthen `PIIScrubber.PII_PATTERNS`:
  - make US phone detection accept parentheses, spaces, dots, hyphens, and optional country code.
  - make international phone detection more robust while avoiding partial digit matches.
  - make street address detection require an actual street-type suffix and avoid overmatching.
- Add Hypothesis tests in `tests/unit/test_pii_scrubber.py` for:
  - preserving non-PII text
  - redacting valid PII values generated by Hypothesis
- Use direct `PIIScrubber()` instantiation inside Hypothesis tests, not a pytest fixture.
